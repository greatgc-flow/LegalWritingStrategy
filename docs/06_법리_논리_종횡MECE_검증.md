# 법리·논리·증거·문체의 재귀적 MECE 및 종횡 교차검증

## 1. 객체 모델(정답이 아니라 추적 체계)

객체 ID와 필수 연결은 `docs/00_최종_통합마스터_V5.md` §1.1의 단일 표를 따른다. 사용자/절차 요구는 `R`, 불리자료·반론은 `ADV`이며, 실제 연결·방향은 `scripts/strategy_qa.py`의 `SCHEMA`에 맞춘다.

MECE의 **상호 배타**는 '관리 책임의 중복 최소화'에 적용한다. 하나의 문자메시지가 여러 주장·요건을 뒷받침하면 **다대다 연결**을 허용한다. 현실 증거 자체를 억지로 분리하면 오히려 왜곡될 수 있다.

## 2. 법리 검증 알고리즘

1. 문서 유형/기관/사건번호/당사자/작성일/기한/관할/적격을 기록.
2. 검토할 **청구권·구성요건·절차요건**을 각각 독립 ID로 분해.
3. 법령 명칭·조문·개정 연혁·시행일·부칙/적용례를 국가법령정보센터 원문으로 확인.
4. 판례는 **실재 여부, 법원·선고일·사건번호, 쟁점 일치, 핵심 판시의 정확한 위치, 최신 판례·변경 여부**를 검증.
5. 각 요건에 필요한 입증 사실을 열거하고 `FACT ↔ EV` 맵핑. 고의·기망·처분행위·인과·손해 등은 자동 추정하지 않음.
6. 강한 반론·대안설명·유리한 증거 및 사실/법적 불확실성을 별도 기록.
7. 검증된 범위에 맞춰 `확인된다`, `시사한다`, `가능성이 있다`, `확인할 필요가 있다` 등 강도 조절.
8. 수사단계/공소제기/형사판결에서 요구하는 판단과 증명 수준을 동일시하지 않음.
9. 구조/문체 편집 후 3~8을 다시 실행.

## 3. 논리적 오류 자동/수동 탐지

- 전건긍정/후건긍정 혼동, 필요·충분조건 혼동, 시간순서를 인과로 오인, 상관관계=공모, 결론을 전제로 한 순환, 일부 거래로 전체 거래 확대, 결론의 과잉 확정, 선택된 증거만 제시, 부정사실을 추정으로 확정.
- `사실 A` → `추정 B`의 화살표에는 **독립 근거** 또는 미검증 표기를 요구한다.
- 단일 서술에 2개 이상 논점이 섞이면 분리하되 사건의 문맥은 유지한다.

## 4. 독자별 검증

| 독자/단계 | 필요한 문장 | 위험한 문장 |
|---|---|---|
| 수사관 | 확인해야 할 사실과 조사 방법을 구체적으로 표시 | 미확인 사실을 수사 완료 사실로 단정 |
| 검사 | 구성요건별 입증자료와 반론까지 분석 | '기소하라'는 감정적 압박, 증거 없는 기망/고의 단정 |
| 법관 | 증거와 증명책임, 쟁점별 법적 판단을 구별 | 무죄추정·자유심증·증명기준 무시 |
| 민사 재판부 | 청구취지/요건사실/입증책임과 증거 연결 | 소송물 및 금액산정 근거 누락 |

**인용성 테스트:** 각 핵심 문단을 맥락에서 떼어 내어도 `누가/언제/무엇/원증거/의미/한계`를 오인하지 않을까? 짧은 인용문을 원본과 문자 단위 비교했는가? 잘 만든 문장 수를 유죄/기소율로 환산하지 않는다.

## 5. 종방향 검사 (V1~V5)

- V1: 제출목적 → 법률요건 → 주장·증거 → 결론으로 전진 추적.
- V2: 모든 핵심 문장의 사실과 수치 → 원증거까지 역추적.
- V3: 모든 법률 결론 → 시점 맞는 조문·판례·적용 범위 역추적.
- V4: 목차의 주장과 각 문단의 주요 결론이 누락 없이 연결.
- V5: 원본 기존 서면과 수정본의 사실·법적 효과·인용 의미 대조.

## 6. 횡방향 검사 (H1~H8)

- H1: 인명/역할/직함/별칭 표기 일치.
- H2: 날짜/거래 금액/계좌/통화 단위/합계 일치.
- H3: 법령명/버전/시행일/부칙/판례 인용 일치.
- H4: 확인/추정/진술 등 사실 확정 수준 일치.
- H5: 본문 인용↔증거목록↔첨부 파일명/페이지/타임코드 양방향 일치.
- H6: 중복 문단 간 의미 충돌 및 불필요한 반복 여부.
- H7: 반대증거와 미확인 항목을 특정 장에서 숨기지 않았는가.
- H8: 표/그래프/선/라벨/도표 출처가 본문·원증거와 일치.

## 7. 재귀적 수정·중단 알고리즘

- 법령/판례 오류 → P2로 되돌림 → 법리 영향을 받는 모든 ISS/PAR/VIS 재검증.
- 사실/원본 인용 변형 → P1로 되돌림 → 관련 문단 재작성 및 H2/H4/H5 확인.
- 반대증거 누락 → P3 → P4 구조/결론 및 P5 문체 재평가.
- 글자 깨짐/표 잘림 → P7 → 문단 흐름/제목/쪽번호 재평가.
- 재귀 반복 후에는 **새 중대한 오류 0**, 기존 중요한 오류 모두 해소·명시, 검증 상태 부여, 사람 승인으로 종료.
- **핵심 게이트:** G1~G7의 정의와 미충족 시 조치는 `docs/00_최종_통합마스터_V5.md` §13.2의 단일 게이트 표를 따른다. 실제 제출 포맷·환경에서 직접 검증하고, 미실시 항목은 확인 완료로 표시하지 않는다.

## 8. 제출 전 교차점검 체크리스트

- [ ]  법적 효과가 달라지는 '않는다/없다/아니다/할 수 있다' 표현을 AI가 임의 변경하지 않았는가.
- [ ]  모든 핵심 인용문이 원본과 일치하며 발췌 생략이 왜곡을 만들지 않는가.
- [ ]  같은 수치가 본문·표·그림·증거목록에 동일하게 표시되는가.
- [ ]  원본/전사/소유자 진술/AI 추론/객관 자료 등급을 구분했는가.
- [ ]  형사·민사 절차와 적용 시점별 규정을 구분했는가.
- [ ]  반론과 불리한 자료를 모두 검토하고 무리한 확정 표현을 피했는가.
- [ ]  제목은 주제/쟁점을 가리키고 불필요하게 판단을 선취하지 않는가.
- [ ]  사람이 실제로 작성한 절제된 문체인가. 메타성 AI 문구가 제출 본문에 없는가.
- [ ]  표의 열/행/단위/소계/각주/출처/분할 인쇄에 문제가 없는가.
- [ ]  파일 이름/버전/작성일/최종승인자/해시/접수용 최종본을 식별할 수 있는가.
