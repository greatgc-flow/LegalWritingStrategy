> 동결일 2026-11-09. 점수는 `python scripts/score.py`가 아래 술어로 **계산**한다(사람이 숫자를 쓰지 않는다). 점수는 작성체계 내부 구조의 완결도이며 승소·기소·유죄·제출 적합성의 보증이 아니다. 루브릭을 바꾸면 이 파일과 `scripts/score.py`를 함께 바꾸고 이력을 남긴다(점수 목표를 위한 사후 수정 금지).

## 2. SG1-SG4 (release gates of score.py)

SG1 비밀·실사건 자료 패턴 없음(토큰, 주민번호·계좌번호 형태) · SG2 면책 문구(승소·기소·유죄 비보장, 변호사 검토) 존재 · SG3 "승소 보장"류 문구 부재 · SG4 모든 합성 예제가 가상임을 표시. 하나라도 실패하면 점수와 무관하게 배포 차단한다.

사건별 제출 게이트 G1~G7은 `docs/00_최종_통합마스터_V5.md` §13.2의 단일 표를 따른다. 위 배포 검사를 통과해도 사건별 제출 검증을 대신하지 않는다.

## 3. 점수 제외 (NOT_TESTED로만 보고)

실제 사건의 사실·증거 전수 역추적, 법률 전문가·독자(경찰·검사·법관) 평가, HWP 데스크톱 설치 실기기, 논문 53건 전문 방법론 검토, 판결 결과. 이들은 100점의 분모에 포함되지 않으며 "검증되었다"로 표기하지 않는다.

## 4. 종/횡 요약

- 종: 요구(R) → 절차(S0) → 쟁점(ISS) → 요건(LAW) → 사실(FACT) → 원증거(EV) → 주장(ARG) → 문단(PAR) → 도표·첨부(VIS/ATT) → 변경(CHG) → 감사(QA), 정·역방향 도달성은 `strategy_qa`가 검사한다.
- 횡: 같은 사람·날짜·금액·조문·증거번호가 모든 문서에서 같은 값(H1~H8)이며, 변경은 영향받은 노드를 재감사하고 종료 상태에서 멈춘다.
- 근거 구분: 학술 근거(`research_register.csv`)와 법적 권위(`statute_ledger.csv`)는 별도 장부이며 서로 대체하지 않는다. 로컬 법령 저장소(legalize-kr)는 조회 보조이지 공식 원문이 아니므로 제출 직전 국가법령정보센터로 재확인한다.

## 5. 재현
