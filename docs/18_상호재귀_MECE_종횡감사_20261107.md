## 1. 핵심 판정

- **패키지 내부 설계·자동검증 완결도 88/100점**(아래 자체 루브릭, 수정 후).
- **실제 사건 제출 적합성은 NOT_TESTED**. 법률 원문, 부칙의 사건별 적용, 원증거 진정성·증명력, Windows/HWP 출력 및 법률 전문가 검토는 별도 확인해야 한다.
- 연구 색인 53건은 전수 원문 검증이 아니다. 대부분 메타데이터·초록 수준이므로 `evidence_grade`와 `verification_scope`를 혼동하지 않는다.

## 2. 책임영역의 MECE와 객체 연결

| 영역 | 1차 책임 | 결과 |
|---|---|---|
| R 요구 | 목표·요구·상태 | R01~R22 ↔ 절차·문서·검증 |
| S0~S6 전략 | 사건이론·쟁점·법률요건·불리증거·청중 | ISS/LAW/FACT/EV/ARG |
| P0~P8 편집 | 원본 보존·법리·논증·목차·문체·출력·감사 | PAR/VIS/ATT/CHG |
| D01~D12 공통 기준 | 법적·증거적 기준, 문서·서식·보안 | 원칙의 단일 관리 책임 |
| QA | 수직 V1~V5, 수평 H1~H8 및 게이트 | PASS/REVIEW/FAIL·잔여위험 |

MECE는 관리 책임에 적용한다. 실제 증거·요건·주장은 다대다로 연결되고 원증거를 강제로 분할하지 않는다.

## 3. 세로 완결성(정방향·역방향)

`요구(R) → 절차·독자(S0) → 쟁점(ISS) → 적용요건(LAW) → 사실(FACT) → 원증거(EV) → 주장·반론(ARG) → 문단(PAR) → 도표·첨부(VIS/ATT) → 수정(CHG) → 감사(QA)`

- 정방향: 요구마다 담당 규칙, 증빙, 현재 단계, 통과조건과 책임자가 존재하는지 점검한다.
- 역방향: 모든 핵심 문장·금액·인용·화살표가 원문 위치와 적용법으로 돌아가야 한다. 출처가 없다면 `UNVERIFIED`.
- 현재 패키지는 가상 예제만 자동 실증했다. 실제 사건의 전수 역추적은 수행하지 않았다.

## 4. 가로 완결성(H1~H8)

- H1 사람·지위·직함, H2 날짜·금액·계좌·단위, H3 법령 시행일·부칙·판례, H4 사실·추론 등급, H5 증거번호·별첨·원본 위치.
- H6 주장과 소제목의 중복·충돌, H7 불리자료·최강 반론 누락, H8 표·차트·도표·PDF 출력 일치.
- S가 확정한 주장·반론의 ID와 P의 문단·표에 같은 기준을 적용한다. P의 문장 변경이 요건이나 사건이론에 영향을 미치면 S2/S3/S4로 돌아간다.

## 5. 재귀 종료 규칙

1. 수정시 CHG를 기록하고 연결된 ISS/LAW/FACT/EV/ARG/PAR/VIS/ATT를 전후로 탐색한다.
2. 새로운 반론, 반대증거, 근거 부재가 발견되면 이전 단계로 롤백 후 독립 QA한다.
3. 법률·증거의 `verified` 플래그는 불리언 `true`만 수용한다. 그래도 원본 자체가 법적으로 검증되었다는 뜻은 아니다.
4. 인용문·금액의 원문 출처 자체가 없으면 `NO_QUOTE_SOURCE` / `NO_AMOUNT_SOURCE`로 실패한다.
5. 중대한 사실·법률 공백, 자료 왜곡, 보안 유출, 제출 PDF 미검수는 점수에 상관없이 `READY_TO_FILE` 차단.
