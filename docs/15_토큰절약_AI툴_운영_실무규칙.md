# 제15장. AI CLI 상시지침·도구 사용법·토큰 절약 운영 (2026-11-06)

## 왜 필요한가

법률서류에는 수십~수천 페이지 자료가 연결될 수 있다. 긴 맥락에서는 일부 정보의 검색·활용이 불안정할 수 있다(Liu 외 2024). 그러나 비용 절약을 위해 유리한 증거만 보내거나 반대사정을 누락하면 **정확성이 손상**된다. 따라서 전체 자료의 보존과 현재 작업에 필요한 부분의 동적 불러오기를 결합한다.

## 4단계 정보계층 (정적 prefix + 적시 검색)

| 층 | 파일 및 원칙 | 사용시점 |
|---|---|---|
| L0 | `AGENTS.md`, `CLAUDE.md` 짧은 절대규칙, `config/style_profile.json` | 매 요청 자동 또는 최초 |
| L1 | `docs/01_...` 특정 장, 해당 법령·증거 정책 | 관련 범주 시작 때 |
| L2 | 전략 `prompts/strategy/S0..S6`, 수정 `prompts/P0..P8` 중 현재 1~2개 | 작업별 |
| L3 | 사건 `CASE_INDEX.md` + 연관 `EV/LAW/FACT/PAR` ID + 변경 diff | 실제 문서 처리 때 |

**오케스트레이션:** `S0→S1→S2→S3→S4→S5→S6`(법률적 판단 전략)와 `P0→...→P8`(기존문서 수정)를 병렬 정의한다. 프롬프트 파일을 전부 통째로 실어 보내지 않는다. 모델 사용량을 측정할 수 있는 환경에서는 `input_tokens`, `cached_input_tokens`, `output_tokens`, 오류 건수, 인적 검토량을 함께 기록한다.

## 메타데이터·원증거 처리

- 사전 색인 `CASE_INDEX`: 제목, 파일 식별자, 일자, 당사자, 내용유형, 민감도, SHA-256(정본 있는 경우), 원본 페이지/시간, 적용 가능한 쟁점, 검증 상태.
- 기본 검색: `쟁점 ID → 관련 요건 → 직접 관련 EV 전체 원문 구간(전후 맥락 포함) → 반대/상충 증거 → 법령 연혁`.
- 큰 문서는 기계적으로 1,000토큰으로 나누지 않는다. 문맥·발화자·표·계약 조항의 경계에 맞춘다. 인용은 정확 원문 + 파일위치.
- 자동 전사/OCR 결과는 원본 확인이 없으면 `DERIVED_UNVERIFIED`로 표시하고 최종 사실로 승격하지 않는다.
- 중요한 인물·날짜·금액·증거번호는 최소 1회 원본과 양방향 매핑한다.

## 프롬프트 캐싱과 안정적인 접두부

OpenAI API 공식 문서는 `동일한 앞부분(prompt prefix) 재사용`, 안정적인 도구 정의, 동적 정보의 뒤쪽 배치를 설명한다. 캐시의 지원·과금·보존시간은 API 모델·CLI마다 다르다. **CLI에 API 전용 파라미터를 임의로 넣지 말고 해당 CLI 명령 도움말로 확인.**

- **고정:** 역할/윤리/검증 지침, 출력 스키마, 도구 스펙의 순서.
- **가변:** 제출기관, 사건자료, 현재 변경분, 질문.
- **민감자료:** 캐시 설정이나 외부 서버 전송 전에 개인정보·기밀처리 정책 검토. 비공개 저장소를 AI가 접근할 수 있다는 사실이 외부 전송 권한을 의미하지 않는다.
- **최적화 목표:** 호출 횟수만 최소화하는 것이 아니라 `실제 요금 + 재작업 시간 + 오류위험`을 비교.

공식: https://developers.openai.com/api/docs/guides/prompt-caching ; https://developers.openai.com/api/docs/guides/prompting

## 사전등록 도구 스펙 파일

`config/tool_catalog.json`은 실행 가능한 도구 이름·역할·설치확인 명령·출력·주의점을 포함. 실제 OS의 PATH에 없는 도구는 `NOT_INSTALLED`로 표시하며 자동으로 실행하지 않는다.

- PDF 작성·변환 `Pandoc + Word/LibreOffice`; 확인 `pdffonts, PyMuPDF` (`config/tool_catalog.json`의 기본명령 참조).
- AI 분석용 텍스트 추출은 `markitdown-gc`를 사용하며, 기본명령은 `config/tool_catalog.json`을 따른다. 추출문은 원본과 대조한다.
- DOCX 작성/확인 `python-docx`와 실제 PDF 변환 후 페이지·표·글꼴 검수.
- 그래프 `matplotlib`; 관계도 `Graphviz`, `Mermaid CLI`.
- 출처관리 `Zotero`(Word 플러그인 권장), 법령 `국가법령정보센터` 원문 직접 확인.
- **도구 안에 기본 옵션만 적어 놓았다고 실제 실행 검증 완료가 아니다.** 설치 여부와 출력 결과를 기록해야 한다.

## 재현성

- 사건별 `RUN_LOG.json`: 문서 해시, 모델·버전(확인 가능하면), 프롬프트 ID, 참고 원문 해시, 도구 버전, 변경 diff, 결과, 미확인 항목, 검사자 서명.
- 원본 서류는 새 버전으로만 수정한다. 자동 승격 금지. 제출·이메일 발송은 별도 명시 승인 필요.

## 비용 실험 설계

A: 전체 공통지침/전체문서/일괄 수정. B: 짧은 고정지침 + 관련 쟁점·원증거 + 단계별 작업. 동일한 자료·동일한 검증 기준으로 `원문 누락`, `허위 인용`, `사용 토큰`, `총 수행시간`, `재수정 건수` 비교. **원문·반대증거를 빼고 싸게 만든 접근은 성공으로 세지 않는다.**
