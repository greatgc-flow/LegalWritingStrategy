# AI CLI 토큰·비용 절감과 재현 가능한 법률서면 작업

목표: 정확성·기밀·추적성을 희생하지 않고 **중복 문맥 입력을 줄인다**. 여기서 설명하는 토큰·캐시 동작은 제공자와 모델·CLI별로 다르므로 사용량 로그로 실측한다.

## 1. 연구·제품 문서로 확인된 사실

- Liu 외(2024), **Lost in the Middle**, TACL, DOI [10.1162/tacl_a_00638](https://aclanthology.org/2024.tacl-1.9/): 긴 입력의 가운데 있는 중요정보를 놓칠 수 있다는 실험 결과. 최신 모든 모델에서도 반드시 동일한 수치를 보인다는 뜻은 아님.
- Kamoi 외(2024), **When Can LLMs Actually Correct Their Own Mistakes?**, DOI [10.1162/tacl_a_00713](https://aclanthology.org/2024.tacl-1.78/): 외부 피드백이 없는 단독 자기교정은 신뢰할 만한 보증이 아니다.
- OpenAI 공식 [Prompt Caching](https://developers.openai.com/api/docs/guides/prompt-caching): **동일한 프롬프트 접두부**를 재사용하면 지원 환경에서 캐시 효과를 얻을 수 있음. 지원 여부·최소길이·가격·TTL은 모델 및 서비스에 따라 다름. 요청하지 않은 개인정보를 캐시 대상으로 보내지 않는다.
- OpenAI 공식 [API deployment checklist](https://developers.openai.com/api/docs/guides/deployment-checklist): 안정된 지침/예시는 앞에, 바뀌는 작업정보는 뒤에 배치하고 tool 정의의 순서를 안정화하도록 안내한다. API용 옵션을 CLI에 그대로 넣지 말 것.
- OpenAI 공식 [Codex AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md): 저장소 안의 `AGENTS.md`는 간명한 프로젝트 상시지침에 적합. 파일의 존재만으로 메모리 전부가 로드되거나 토큰이 0이 되지는 않는다.
- 참고: **프롬프트 분리 자체가 언제나 단일 호출보다 비용이 적다는 실증은 없다.** 품질·오류율·반복 횟수·캐시 적중까지 비교한다.

## 2. 정보 계층: 항상 / 필요할 때 / 변경된 것만

| 계층 | 파일 | 원칙 |
|---|---|---|
| L0(항상) | `AGENTS.md` 또는 `CLAUDE.md` | 500~1,000자 수준의 필수 통제 원칙·읽을 곳·기밀규칙 |
| L1(요청 시) | `docs/00_최종_통합마스터_V5.md` 등 | 관련 장만 열람, 단순 문체 수정에 전체 연구논문 재전송 금지 |
| L2(단계별) | `prompts/P0`~`P8` | 현재 단계 하나만 로드. 복잡한 교차검증은 P8 추가 |
| L3(업무별) | `cases/<case>/...` | 사건에 필요한 주장ID·증거 인덱스와 **관련 원증거만** 참조 |
| L4(실시간 델타) | 이번 변경분 + diff | 변경 파일/문단만 우선 재검토, 종횡 영향 받은 연결점만 추가 |

**고정 프롬프트 접두부 예시:** `공통보안규칙 → 문서유형·출처등급 규칙 → 검증지표` 순서로 최대한 동일하게 유지하고, 현재 쟁점과 원증거를 뒤에 붙인다. 단, 실제 API 서비스가 접두부 캐싱을 지원하는지부터 확인한다.

## 3. 변경 영향 기반 최소입력 검색

1. `requirements/`에서 요구 ID를 찾는다.
2. 변경할 `ISS`, `FACT`, `EV`, `LAW`, `PAR`의 ID를 읽는다.
3. 해당 ID의 **출처 원문·앞뒤 문맥을 유실하지 않을 범위**에서 가져온다.
4. 연결 그래프의 후속 문단·표·별첨만 검수하되, 결론·요건 변화가 있으면 상위 쟁점 전체를 다시 검사한다.
5. 영향범위가 불확실하면 입력을 줄이지 않고 검증 범위를 넓힌다. **토큰 절약보다 법적 정확성 우선.**

`CASE_INDEX.md` 예시:
```markdown
# CASE_INDEX (실제 사건에는 비공개 경로)
- issue_id: ISS-001
- fact_id: FACT-001
- evidence_id: EV-001
- source_path: private/original/EV-001.pdf
- exact_location: p.3 lines 5-8
- validation: original_verified / transcript_only / owner_statement / unverified
- legal_rule: LAW-001 (시행일 필수)
- affected_paragraph: PAR-012
```

## 4. 프롬프트의 압축은 '정보 제거'와 다르다

**보존 필수:** 주체, 시점, 금액, 원문 인용, 증거번호, 증거 출처 등급, 법령 시행일, 반대증거, 승인 및 변경 내역.

**압축 가능:** 같은 설명을 여러 차례 반복하는 메타 문장, 설치방법, 표준 도구 명령(별도 파일), 이미 검증된 불변 정의, 장문의 실행 로그의 정상 반복 행. **'요약만으로 진실성 확정'하지 않는다.**

## 5. 실무 기본 세션 명령 예시

- **기존 서면 문장 교정만:** `prompts/P5_사람다운문체_정확교정.md` + 변경 전 문단 + 관련 FACT/EV 및 법적 제한 + 수정 목적.
- **증거 인용 오류만:** `prompts/P6_참고증거_표_도표_대조.md` + 본문 해당 절 + 관련 증거 원본 위치 + 전체 증거목록의 대상 엔트리.
- **목차 개편:** `prompts/P4_목차_쟁점배열_설계.md` + 목차 + 쟁점지도 + 충돌·누락 목록; 원본문단 전체는 재배치 승인 시에만.
- **제출 직전:** `prompts/P8_독립감사_종횡_최종판정.md` + 제출후보 전체 문서 + 필수 증거/법리 색인 + 렌더 검사 결과. 고위험이므로 비용 절약 우선하지 않음.

## 6. 사용량 측정 방법

실제 사용 모델/CLI에서 가능한 경우 `input_tokens`, `cached_input_tokens`, `output_tokens`, 호출 횟수, 수동 수정 건수, 검증 실패 건수, 총 시간, 재작업률을 기록한다. 미지원 CLI에서는 토큰 추정치를 실제 과금값이라고 표시하지 않는다.

| 항목 | A: 단일 대형 프롬프트 | B: 단계별·색인형 |
|---|---|---|
| 입력 비용 | 실측 | 실측 |
| 캐시 적중 | 실측 | 실측 |
| 근거 누락 | 유무/건수 | 유무/건수 |
| 사실 변형 | 유무/건수 | 유무/건수 |
| 승인 없는 변경 | 유무/건수 | 유무/건수 |
| 최종 문서 이해도 | 독립 평가 | 독립 평가 |

최저 비용이 아닌 **최저 위험 조건에서 필요한 품질을 달성하는 비용**을 최적화한다.

## 7. 개인정보·로컬 운영

사건 원본을 외부 LLM·웹서비스에 입력할 때는 명시적 권한과 기관·서비스의 처리정책을 확인한다. API 캐시나 프로젝트 파일이 **비밀정보 보호를 자동 보장하지 않는다**. 비식별화도 사건의 실체를 바꾸지 않도록 별도 매핑표를 로컬 보관한다. 민감한 원증거의 공개 Git 커밋 금지, 비공개 저장소에도 최소권한 원칙 적용.
