# Windows 11 / AI CLI 법률문서 도구 설치·설정·사용법

기준일 2026-11-06. 설치는 **Preview(기본) → 원본 출처·라이선스 검토 → 명시적 Apply → 버전·출력 시험** 순서. 도구 기본명령은 `config/tool_catalog.json`을 따른다. 설치·출력 증빙 없이 통과로 단정하지 않는다. 모든 도구를 한꺼번에 설치할 이유는 없다.

플러그인·패키지 버전과 라이선스는 설치 시 공식 출처로 확인한다. `config/tool_catalog.json`은 확인할 명령을 정의한 것이며, 실제 설치나 실행 성공의 증빙을 대신하지 않는다.

## 1. 권장 최소 구성

| 필요도 | 도구 | 핵심 역할 | 공식 자료 | 설치/확인 |
|---|---|---|---|---|
| 필수 | Python 3.12+ | 자동 문서·검증 | https://www.python.org/downloads/windows/ | `py --list` |
| 필수 | LibreOffice | DOCX→PDF / 화면 출력 확인 | https://www.libreoffice.org/download/download-libreoffice/ | `soffice --version` 또는 GUI |
| 권장 | Pandoc | MD→DOCX 변환, **reference.docx** 활용 | https://pandoc.org/installing.html | `pandoc --version` |
| 권장 | Git | diff·버전·변경 추적 | https://git-scm.com/downloads/win | `git --version` |
| 권장 | Zotero | 연구문헌 출처/서지 정리 | https://www.zotero.org/download/ | GUI로 확인 |
| 도표 | Graphviz | 인과·인물·자료 관계도 | https://graphviz.org/download/ | `dot -V` |
| 도표 | Node.js LTS | Mermaid CLI 전제 런타임 | https://nodejs.org/ | `node -v; npm -v` |
| 도표 | Mermaid CLI | 사건 흐름도·시퀀스 | https://github.com/mermaid-js/mermaid-cli | `mmdc --help` |
| PDF | PyMuPDF | 글자 추출·페이지/링크 QA | https://pymupdf.readthedocs.io/en/latest/installation.html | `python -c "import fitz;print(fitz.VersionBind)"` |
| DOCX | python-docx | 문서 스타일·표·설정 | https://python-docx.readthedocs.io/ | `python -c "import docx;print(docx.__version__)"` |
| 추출 | markitdown-gc | AI 분석용 Markdown 추출; 원본과 별도 보존 | `config/tool_catalog.json` | `markitdown-gc --version` |
| 표·차트 | openpyxl, matplotlib | 데이터 표·도표 | `config/tool_catalog.json` | 카탈로그의 확인 명령 참조 |
| PDF | Poppler / `pdffonts` | PDF 폰트 포함 확인 | `config/tool_catalog.json` | `pdffonts -v` |

업무 장비에 기존 Python/Node/오피스 버전이 있다면 덮어쓰지 않는다. Python은 `.venv` 격리. 폐쇄망 환경에서는 신뢰된 사내 배포물과 보안승인을 우선한다. 회사 PC라면 설치권한·보안정책이 우선한다. 설치 성공 여부는 사용자 PC에서 직접 확인한다.

## 2. 최소 설치 명령 — 공식 WinGet 원칙

```powershell
winget --version
winget search --id Git.Git
winget show --id Git.Git
winget install --id Git.Git -e --source winget
# search/show에서 ID를 확인한 후 winget install --id <확인된ID> -e
```

확인용 패키지 ID: `Git.Git`, `JohnMacFarlane.Pandoc`, `TheDocumentFoundation.LibreOffice`, `Python.Python.3.12`, `Graphviz.Graphviz`, `DigitalScholar.Zotero`, `OpenJS.NodeJS.LTS`. 공식 `winget` 설명: https://learn.microsoft.com/ko-kr/windows/package-manager/winget/install . **`winget search/show`로 실제 패키지를 확인한 뒤 설치**하므로 잘못된 패키지 ID나 무의식적인 자동 갱신을 방지한다.

`scripts/install_windows.ps1`은 기본 Preview이며 `-Apply`를 붙여도 항목별 YES 확인 후에만 설치한다. Mac/Linux는 명령과 보안 동작이 다르므로 이 PowerShell 스크립트를 그대로 실행하지 않는다.

```powershell
.\scripts\install_windows.ps1
.\scripts\install_windows.ps1 -Apply
```

## 3. Python 가상환경 + 의존성 + 기본 QA

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m unittest discover -s scripts -p 'test_*.py' -v
.\.venv\Scripts\python.exe scripts\legal_qa.py --record examples\synthetic_case.json
.\.venv\Scripts\python.exe scripts\strategy_qa.py --record examples\synthetic_strategy_case.json
```

PowerShell에서 `Activate.ps1` 실행이 보안정책 때문에 막히더라도 `.venv\Scripts\python.exe` 직접 실행이면 충분하므로 전역 실행정책을 바꾸지 않는다. AI 세션에는 `README.md` → `AGENTS.md` → `config/tool_catalog.json` → 현재 단계 프롬프트만 읽히면 긴 도구 설명의 반복 전송을 줄일 수 있다.

`py` 명령이 없으면 설치된 Python 3.12 실행 파일의 절대 경로로 `-m venv .venv`를 실행한다. 기존 `.venv`가 있다면 먼저 `.\.venv\Scripts\python.exe --version`으로 버전을 확인하고, 다른 버전의 환경을 덮어쓰지 않는다.

## 4. 도구별 실제 사용 예

아래 예제는 패키지 루트에서 실행한다. 출력 폴더를 먼저 만든다.

```powershell
New-Item -ItemType Directory -Force output | Out-Null
```

**Git — 변경 내용 대조**
```powershell
git diff --word-diff
```
원본은 보존하고 작업본의 차이를 확인한다. 일반 텍스트 diff만으로 표·각주·서식까지 검증했다고 보지 않는다.

**markitdown-gc — 분석용 텍스트 추출**
```powershell
markitdown-gc original.docx -o original_for_ai.md
```
카탈로그의 확인 명령으로 사용 가능 여부를 먼저 확인한다. 미설치 도구는 자동 실행하지 않으며, 추출문은 제출용 원본과 구분하고 원문·표·인용을 대조한다.

**Pandoc — 템플릿을 이용한 편집 가능 DOCX**
```powershell
pandoc docs\00_최종_통합마스터_V5.md -f gfm -o output.docx --reference-doc templates\civil_A4_reference.docx
```
주의: Pandoc은 스타일을 참고하지만 법률 내용·각주·표가 정확하게 변환되었다고 보장하지 않는다. 표의 페이지 잘림과 번호를 사람이 확인한다. https://pandoc.org/MANUAL.html

**LibreOffice — 제출 후보 PDF 변환**
```powershell
soffice --headless --convert-to pdf --outdir output output.docx
```
포터블/미설치 PC는 한컴오피스/Word의 파일→PDF 내보내기로 대체하고 전 페이지 수동 검수.

**PyMuPDF — 변환한 PDF의 기술 검사**
```powershell
.\.venv\Scripts\python.exe scripts\legal_qa.py --pdf output\output.pdf
```
위 LibreOffice 예제로 PDF를 만든 뒤 실행한다. 자동 검사는 페이지·텍스트 등의 보조 검사이며 전 페이지 육안 검수를 대신하지 않는다.

**Graphviz — 신뢰 등급을 붙인 관계도**
```powershell
dot -Tsvg examples\evidence_relationship.dot -o output\relationship.svg
```
관계선마다 `EV-XXX` 연결을 명시하고 검증되지 않은 연결은 점선/의문으로 구분. SVG는 원본 좌표가 유지되도록 검수한다.

**Mermaid — 검토 절차**
```powershell
# Node.js LTS / npm 필요
npm install -g @mermaid-js/mermaid-cli
mmdc -i examples\revision_pipeline.mmd -o output\pipeline.svg
```
https://github.com/mermaid-js/mermaid-cli . 설치 중 Chromium/Puppeteer 내려받기가 필요한 환경이 있으므로 폐쇄망에서는 Graphviz 대안을 우선.

**Python 차트 — 금액·기간**
```powershell
.\.venv\Scripts\python.exe examples\plot_transaction.py
```
`examples/transaction_demo.csv`는 가상 금액. 그래프에서 단위/축/0 기준/출처/기간을 표시하고 수동 비교.

**Zotero — 서지 검증**
1. 논문 DOI/제목으로 Zotero에 추가하고 저자·연도·제목·학술지·권호·페이지·DOI를 확인한다.
2. 미확인 서지는 제출문서의 근거로 사용하지 않는다.
3. 원문 PDF·발행기관의 문서와 첨부 파일을 연결하되 라이선스 없는 논문 PDF를 ZIP에 재배포하지 않는다.

## 5. 문서 스타일 기본값

- `templates/민사_A4_reference.docx`: A4 세로, 상45/하30/좌우20mm, 본문 12pt, 1.5줄 이상, 제목 16/14/12pt. 사용자 환경에서 일치 검증 필요.
- `templates/형사_의견서_가상서식.docx`: 법적 의무로 오인되지 않도록 '참고 서식 / 접수기관 기준 우선' 표시.
- 한글과 Word에서 line spacing UI 표기가 다를 수 있으므로 **내보낸 PDF 실측 확인**. 워드/한글에서 본문 글꼴이 대체되면 레이아웃이 바뀔 수 있다.
- 3색 이상 사용 금지라는 **법적 강행규정은 없다**. 실무에서는 검정 기본 + 한 가지 강조색을 안전 기본값으로 권장한다. 최종 흑백 인쇄에서도 의미 전달 확인.

## 6. 출력/접수 전 품질 게이트

- 폰트 포함/대체/색상, 12pt, 줄간격, A4 여백, 번호/목차, 표/글자 잘림, 링크, 첨부누락, 인용문 동일성, 증거목록 양방향 일치.
- 파일 메타데이터(작성자·최근 저장 기록), 숨겨진 검토 메모·주석, 개인식별정보를 점검. 수사/재판 증거의 **원본을 임의로 영구 수정하지 않는다**.
- 형사·민사 신청기한, 접수기관의 필수 서식, 스캔·전자서명 요구와 보정요청은 당일 재확인.
- `qa/FINAL_REVIEW_CHECKLIST.md`에는 항목별 검사 결과를 **PASS/FAIL/REVIEW/NOT_TESTED**로 남긴다. 도구가 설치되지 않은 사용자 PC는 NOT_TESTED. 문서 최종 판정은 `READY_FOR_HUMAN_REVIEW / NEEDS_VERIFICATION / SUBMISSION_BLOCKED` 중 하나로 기록하며 사람의 검토·제출 승인은 별도다.

## 7. 고장·충돌·보안 대응

- `winget` 없음: Microsoft Store의 **App Installer** 또는 조직 IT 관리자 승인 설치.
- `soffice` 명령 없음: LibreOffice 설치 디렉터리의 프로그램을 절대 경로로 실행, `where.exe soffice`로 확인.
- 글꼴 대체: 해당 폰트 설치 확인→편집기 재시작→PDF 변환→PDF에서 텍스트 검색·폰트 포함 확인.
- Mermaid 실패: Node 버전·회사 프록시·브라우저 실행권한 확인, Graphviz로 우회.
- 한컴(HWP/HWPX): 수신기관이 요구하는 **원본 편집기에서 열고 저장·출력해 수작업 검수**. 본 패키지는 HWP 자동 변환 성공을 보증하지 않는다.
- 폐쇄망: 외부 CDN·웹 API에 증거/사건 파일 업로드 금지, 설치 프로그램 SHA-256·서명 및 라이선스 검토.
