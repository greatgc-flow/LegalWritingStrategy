# REVISE — 기존 문서 수정

공통 규칙: [공통 지침](../00_공통규칙.md). 실행 계약: [모드 카탈로그](../../config/mode_catalog.json). 사용법: [실행 안내](../../docs/workflow_modes.md).

기존 문서의 승인된 범위만 새 사본에서 수정한다. 원본·이미 제출된 파일을 교체하지 않는다.

## 입력과 범위
기준 버전, 증거 목록, 수정 목적, 변경 가능한 범위와 보존할 법적 의미를 확인한다. 문체 교정·구조 재배치·사실/법리 변경을 구분한다. 입력이 불완전하면 가능한 진단과 필요한 확인을 먼저 반환한다.

## 실행
기존 P0부터 P8까지의 절차를 재사용한다. 원본을 읽고 사실·법리·반론을 진단한 다음 구조 변경안을 만든다. 승인 범위에서 수정하고 인용·서식·독립감사를 수행한다. 단순 교정은 영향 없는 단계의 생략 이유를 남길 수 있지만 원본 보존과 관련 사실검증·최종감사를 생략하지 않는다.

## 인계
수정본, 변경 전후 차이, 변경 이유·근거·영향 문단, 남은 확인사항을 반환한다. 인물·날짜·금액·부정어·인용문·청구취지·법적 책임의 의미가 달라지면 변경 근거와 승인을 따로 남긴다. 표·각주·필드·변경추적은 문자 비교만으로 보존했다고 선언하지 않는다.

## 완료 조건
원본이 불변이고 주요 삭제·추가·이동이 추적된다. 의미 변경은 승인 범위 안에 있으며 연결된 주장과 증거를 재검증했다. 본문 재작성보다 기존 서면의 안전한 개선을 우선한다.

미실시 항목은 `NOT_TESTED`로 기록한다. 최종 판정은 공통 기준의 세 값만 사용하며 이 안내나 실행계획만으로 제출 적합성을 판단하지 않는다.
